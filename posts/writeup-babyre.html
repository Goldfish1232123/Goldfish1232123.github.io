writeup-入门逆向

2026-09-27 · CTF Bugku Reverse

📌 题目信息

  • 题目名： 入门逆向
  • 题目平台： Bugku CTF（平台题）
  • 题目类型： Reverse / PE32 静态分析
  • 题目描述： 来源：XJNU
  • 题目附件： 压缩包，解压后是一个 baby.exe（40KB，PE32）
  • 涉及工具： IDA（或任意反汇编器）、Python

💥 解题过程

  1. 双击运行 baby.exe，只打印一行就退出了： 
    Hi~ this is a babyre
    没有输入框、也没输出 flag——说明 flag 要么藏在数据里，要么藏在代码里，需要静态分析。
  2. 把这个 exe 拖进 IDA（第一次加载全选默认选项，一路 OK 即可）。
  3. 先看 Exports/函数列表，找到入口附近的 _main；按 F5 反编译，得到的 C 代码非常"干净"： 
    int __cdecl main(int argc, const char **argv, const char **envp)
{
  __main();
  printf("Hi~ this is a babyre");
  return 0;
}
    ——main 里根本没有 flag 相关的逻辑。
  4. 回到汇编视图，发现 main 里在 printf 之前有一大串这样的指令： 
    mov     byte ptr [esp+2Fh], 66h    ; 'f'
mov     byte ptr [esp+2Eh], 6Ch    ; 'l'
mov     byte ptr [esp+2Dh], 61h    ; 'a'
mov     byte ptr [esp+2Ch], 67h    ; 'g'
mov     byte ptr [esp+2Bh], 7Bh    ; '{'
mov     byte ptr [esp+2Ah], 52h    ; 'R'
...
    程序在往栈上"逐字节"拼一个字符串——这就是 flag！
    小技巧：在 IDA 里选中这段数据按 R 键（Convert to string），它就会直接显示成字符串。
  5. 按照 [esp+2Fh] → [esp+2Eh] → …… 的顺序把每个立即数取出来，就是完整的 flag： 
    flag{Re_1s_S0_C0OL}
  6. 也可以用 Python 直接从 .text 段批量提取（模式固定为 C6 44 24 XX YY，XX 是栈偏移，YY 就是要的字符）： 
    import re
raw = open("baby.exe", "rb").read()
text = raw[0x400:0x400+11264]              # .text 段
chars = [m.group(2)[0] for m in re.finditer(rb"\xc6\x44\x24(.)(.)", text, re.DOTALL)]
print("".join(chr(c) for c in chars))      # flag{Re_1s_S0_C0OL}

📝 收获

这道题的考点

逆向入门三件事：找到 main、读懂反编译结果、在汇编里找出"数据是怎么被拼出来的"。这题的巧妙之处在于：字符串不是作为常量放在数据段，而是被拆成一条条 mov 指令写进代码里。

原理：为什么 flag 不在 printf 里

  • 正常程序里，字符串常量会放在 .rdata 段，用 strings 就能直接看到。
  • 出题人故意把 flag 拆成一个个字节，用 mov byte ptr [栈地址], 立即数 逐条指令往栈上写——这样：① 用 strings 搜不到；② 反编译 main 也看不出来（Hex-Rays 把它优化掉了/没当字符串处理）。你必须看汇编，或者在 IDA 里手动按 R。
  • 它最终没有打印这个字符串（main 里只有那行 printf），所以只能靠静态分析拿到。

可复用的思路（下次遇到同类题）

  1. 第一步永远是运行一下：看它要不要输入、打印什么，这决定了后面是"动态调试"还是"纯静态分析"。
  2. 用 strings（或 Python 版）先扫一遍：如果 flag 是明文常量，这一步就结束了。
  3. 拖进 IDA → 找 main / WinMain → 按 F5 看伪代码；伪代码里没有线索就回到汇编，重点找 mov ... , 立即数 的连续序列、xor 运算、字符串比较（strcmp）等。
  4. 看到连续写栈的字节序列，就在 IDA 里选中 → 按 R 转字符串，或者写脚本批量提取立即数。
  5. 动态分析（x64dbg）可以配合：在 printf 前下断点，看栈上拼好的字符串。

延伸知识

  • PE32 文件结构：DOS 头 → PE 头 → 节区表 → 各节区（.text 代码、.data 已初始化数据、.rdata 只读数据、.idata 导入表）。这题的 .text 在文件偏移 0x400、大小 11264 字节。
  • C6 44 24 XX YY 这条指令的含义：C6 = mov r/m8, imm8；44 24 XX = ModRM（[esp+XX]）；YY = 要写入的字节。看懂这个规律就能用一行正则把所有字符扒出来。
  • IDA 里常用快捷键：F5 反编译、R 转字符串、N 重命名、X 查看交叉引用、G 跳转地址。

防御视角

从"保护"角度说，把敏感字符串拆散成指令只能防住 strings 这种初级手段，静态分析依然能还原——真正的密钥必须用加密 + 运行时派生（或者干脆不放在客户端）。

踩坑提示

  • 只运行一次看到只打印一行，别就此放弃——逆向题的重点是"读代码"，不是"运行程序"。
  • Hex-Rays 的伪代码可能会"吃掉"这类逐字节写栈的代码（显示为一堆 v1[0] = 102; v1[1] = 108; 之类），要能看出这其实是在拼字符串。
  • 栈偏移是递减的（0x2F → 0x2E → … → 0x1D），拼接顺序就是按指令出现顺序，别按地址顺序排。
