矛盾

2026-09-27 · Web Bugku CTF

📌 题目信息

  • 题目名： 矛盾
  • 题目平台： Bugku CTF（平台题，需启动场景）
  • 题目类型： WEB / PHP 弱类型比较
  • 题目描述： 矛盾
  • 靶机地址： 启动场景后形如 http://160.202.254.160:14299/（每人不同，会过期）
  • 涉及工具： 浏览器（或 curl / Burp Suite）

💥 解题过程

  1. 启动场景，打开首页——页面直接把后端代码贴上来了： 
    $num=$_GET['num'];
if(!is_numeric($num))
{
  echo $num;
  if($num==1)
    echo 'flag{**********}';
}
  2. 读逻辑，题目名"矛盾"就体现在这两个条件上：
    • 第一关：!is_numeric($num) —— 要求 num 不是数字；
    • 第二关：$num == 1 —— 又要求它等于 1。
    正常传 ?num=1 会被第一关挡住（is_numeric("1") 为真，取反后条件不成立）。
  3. 突破口是 PHP 的弱类型比较：== 在"字符串 vs 数字"比较时，会把字符串转成数字再比。而 is_numeric() 的判定更严格。于是只要找到"能被转成 1、但 is_numeric 认为不是数字"的字符串即可。
  4. 构造 payload 逐一测试（这题用的 PHP 5.5，几种都通）：
    payloadis_numeric== 1结果
    ?num=1%00（尾部空字节）falsetrue✅ 出 flag
    ?num=1%20（尾部空格）falsetrue✅ 出 flag
    ?num=1afalsetrue✅ 出 flag
    ?num=%201（前导空格）true—❌ 被第一关挡住
    ?num=1 / 0x1 / truetrue—❌ 不出
  5. 用 curl 直接验证： 
    curl "http://目标地址/?num=1%00"
    返回： 
    1 flag{3397d364f8f96258f337b16454a07db4}
    （前面那个 1 是代码里的 echo $num; 回显）
  6. 提交 flag，通过。
  7. ⚠️ 这题的 flag 是"每个场景随机生成"的：每次点「启动场景」，靶机都会生成一个新的 flag。 我第一次解出来的是 flag{4949567ccd1b99e18193f4c122d0f356}，但准备提交时该场景已经过期， 平台提示"flag 不正确"；重新启动场景后拿到的是 flag{3397d364f8f96258f337b16454a07db4}。 正确做法：在场景有效期内、用当前场景返回的 flag 提交。

📝 收获

这道题的考点

PHP 的弱类型比较：同一个值在 is_numeric() 和 == 眼里可以有完全不同的"身份"，出题人就是利用这个差异制造"矛盾"。

原理：为什么 1a 既不是数字又等于 1

  • is_numeric() 只认"完整合法的数字写法"：1、1.5、1e3、0x1（部分版本）——1a、1 （尾部空格）、1\\0 一律返回 false。
  • 但 == 在比较"字符串和数字"时，会按 PHP 的转换规则把字符串转成数字：(int)"1a" = 1、(int)"1 " = 1、(int)"1\\0" = 1，所以它们都 == 1 成立。
  • 两个函数对"边界输入"的处理不一致 → 就出现了"既不是数字，又等于 1"的输入，这就是题目"矛盾"的含义。

可复用的思路（下次遇到同类题）

  1. 看到"既要不是数字、又要等于某个数"，直接想到这几种 payload：1a、1%00、1%20、1.0、1e0。
  2. 看到"两个哈希/字符串相等"（如 md5($a) == md5($b)），想到 0e 魔术哈希（QNKCDZO、240610708 等）或用数组绕过（?a[]=1&b[]=2，md5 对数组返回 null，null == null 成立）。
  3. 看到 strcmp() 比较，想到用数组绕过（PHP 5 里 strcmp(数组, 字符串) 返回 NULL，!NULL 为真）。
  4. 看到 intval() / 类型转换，想到截断、小数、科学计数法、前导零。
  5. 用 Burp / curl 发包最稳，浏览器地址栏有时会把 %00 之类特殊字符吞掉。

延伸知识

  • 版本差异很重要：PHP 8 起，字符串与数字的比较改成了"更符合直觉"的规则——"1a" == 1 在 PHP 8 中变成 false。所以老 writeup 里的 payload 在新版本可能失效，做题时要留意目标 PHP 版本（这题响应头里就有 X-Powered-By: PHP/5.5.9）。
  • 相关的高频考点：0e 魔术哈希、md5()/sha1() 数组绕过、strcmp 数组绕过、%00 截断、intval 截断、php://input 传参。
  • 信息收集小技巧：响应头会暴露技术栈（Server、X-Powered-By），知道是 PHP 5.5 就能推断出哪些"魔术"可用。

防御视角

  • 比较时优先用 ===（严格比较，类型和值都要一致），能避免绝大多数弱类型绕过。
  • 对输入做白名单校验（明确允许的字符集/格式），而不是"不等于某值就放行"。
  • 不要把用户输入直接参与类型敏感的判断（如"是数字就当成数字用"这种假设）。
  • 及时升级 PHP：语言层面的宽松规则本身就是一类漏洞来源。

踩坑提示

  • 遇到"动态 flag"题不要慌：靶机重启/场景过期后旧 flag 就失效了，提交前先重新访问一次靶机确认当前返回的 flag。
  • %00 必须用 URL 编码形式，不能直接敲空字节；浏览器地址栏可能自动处理掉，建议用 curl 或 Burp。
  • 这题用 ?num=1%20（尾部空格）也能过，但要注意"前导空格"（%201）会被 is_numeric 当成合法数字，反而过不了——尾部合法、前导不合法，这个区别很容易混淆。
  • 页面同时回显了 $num（echo $num;），所以看到"1 flag{...}"这种输出不要以为是两个字段。
