writeup-眼见非实

2026-09-27 · CTF Misc

📌 题目信息

  • 题目名： 眼见非实
  • 题目平台： Bugku CTF（平台题）
  • 题目类型： MISC / 文件类型伪装（Office 文档解包）
  • 题目描述： flag{}
  • 题目附件： 一个压缩包，解压后得到 眼见非实.docx
  • 涉及工具： 解压工具（7-Zip / Python 的 zipfile）、文本编辑器

💥 解题过程

  1. 题目名"眼见非实"本身就是提示：你看到的不一定是真的——也就是"扩展名会骗人"。
  2. 下载得到的是一个压缩包，解压后是一个 眼见非实.docx。
  3. 双击用 Word 打开——报错，提示文件损坏/无法打开。这里就是第一个"眼见非实"：它虽然叫 .docx，但内部结构并不符合 Word 的要求（这个 docx 里的文件被套在了一个 眼见非实/ 子目录下，而正常的 docx 所有条目都必须在压缩包根目录，所以 Word 认不出来）。
  4. 换个思路：docx 本质上就是一个 zip 包。用 7-Zip 打开它（或把后缀改成 .zip 再解压），果然解开了一堆 XML： 
    [Content_Types].xml
_rels/.rels
docProps/app.xml
docProps/core.xml
word/document.xml          ← 正文在这里
word/styles.xml
word/theme/theme1.xml
...
  5. 有意思的是：解压出来的条目名前都带着一层 眼见非实/ 目录，这也印证了刚才 Word 打不开的原因。
  6. 正文在 word/document.xml 里（它保存着文档的文字内容）。直接搜关键字： 
    grep -r "flag" ./
# 或
python -c "import re;print(re.findall(r'flag\{[^}]*\}', open('word/document.xml',encoding='utf-8').read()))"
  7. 在 word/document.xml 里找到了 flag。有意思的是它被放在一个带 <w:vanish/> 标记的"run"里： 
    <w:rPr><w:vanish/></w:rPr><w:t>flag{F1@g}</w:t>
    w:vanish 就是 Word 的"隐藏文字"属性——在 Word 里默认根本不显示。所以这题其实是"双重眼见非实"：文件名骗你一次，隐藏文字再骗你一次。
  8. 最终 flag： 
    flag{F1@g}
    （注意用了 leet 写法：F1@g = Fl@g，1 代替 l，@ 代替 a）
  9. 提交通过。

📝 收获

这道题的考点

两件事：文件类型判断不能只看扩展名，以及Office 文档（docx/xlsx/pptx）本质是 zip + XML。

原理：为什么把 docx 当 zip 解开就能看到 flag

  • Office 2007 之后的所有文档格式（docx、xlsx、pptx）都基于 OOXML 标准：一个 zip 压缩包里装着若干 XML 文件。
  • 正文纯文本放在 word/document.xml；样式在 styles.xml；文档属性在 docProps/；嵌入对象、图片、宏分别在各自的目录里。
  • 所以"读一个 docx"和"读一个 zip"在文件层面是一样的——这也意味着文档里的内容（包括隐藏信息）都可以被直接提取出来。
  • Word 打不开的原因也不是"文件坏了"，而是内部条目路径不规范（多了一层目录），Word 的解析器找不到 [Content_Types].xml 的位置。

可复用的思路（下次遇到同类题）

  1. 拿到任何"打不开/报错"的文件，先用十六进制看文件头：50 4B 就是 ZIP（docx/xlsx/pptx/jar/apk 全是它）。
  2. 看到 ZIP 就解压；解压出 XML 结构（[Content_Types].xml、word/、docProps/）说明是 Office 文档。
  3. 然后全文搜关键字：flag、key、ctf；XML 里标签可能把关键字拆开，最好先去掉标签再搜（re.sub(r"<[^>]+>", "", text)）。
  4. 同类伪装还有：把 zip 改名成 jpg/png、把 HTML 改名成图片（改回后缀用浏览器打开）、把 exe 改名成 doc 等等。
  5. 命令行一条龙（Linux/macOS 下最顺手）： 
    file 眼见非实.docx                  # 看真实类型
unzip 眼见非实.docx -d out          # 当 zip 解压
grep -ra "flag" out                 # 递归搜关键字

延伸知识

  • OOXML 关键文件：[Content_Types].xml（声明各部分的类型）、word/document.xml（正文）、word/_rels/（关系表）、docProps/app.xml（页数、字数等属性）。
  • zip 里的中文文件名：早期的压缩工具用 GBK 编码存文件名，在别的系统上解压就会显示成乱码（我这边看到的 ╤█╝√╖╟╩╡.docx 其实就是 眼见非实.docx 被 GBK/UTF-8 混淆的结果）。
  • Office 文档还能藏东西的位置：宏（vbaProject.bin）、嵌入对象（embeddings/）、自定义 XML（customXml/）、文档属性（作者/标题里塞 flag）。

防御视角

两点现实意义：① 服务端做文件上传校验时，只看扩展名是不够的（要看文件头/Magic Bytes），否则"图片马"、伪装文档都能上传成功；② Office 文档可以携带宏，来路不明的文档不要随便点"启用内容"。

踩坑提示

  • Word 报"文件已损坏，无法打开"不代表文件没用——它只是不符合 Word 的解析要求，内容还在里面。
  • 搜 flag 时如果只搜 flag{ 可能搜不到：XML 里文字常被 <w:t> 之类的标签分割，先去掉标签再搜更保险。
  • 文件名乱码是编码问题（GBK ↔ UTF-8），别以为是文件异常。
  • 在 Word 里也可以直接看到隐藏文字：文件 → 选项 → 显示 → 勾选"隐藏文字"，或在"开始"里打开显示编辑标记；当然，直接解压看 XML 更快。
  • 这题 flag 是 flag{F1@g}，注意它是 leet 写法，别"顺手纠正"成 flag{Fl@g} 导致提交失败。
