writeup-POST

2026-09-12 · Bugku Web

📌 题目信息

  • 题目名： POST

💥 解题过程

  1. 把题目代码喂给 DeepSeek，了解到 POST 需要输入 JavaScript 来发送 POST 请求。
  2. 让 DeepSeek 写了请求代码，从浏览器控制台发送，成功获得 flag。

使用的 JavaScript 代码：

fetch('http://160.202.254.160:14947/', {
    method: "POST",
    headers: {"Content-Type": "application/x-www-form-urlencoded"},
    body: "what=flag"
}).then(r => r.text()).then(t => console.log(t));

📝 收获

这道题的考点

POST 传参：数据在请求体里，地址栏改不了，需要借助工具发请求。

原理：为什么这样能拿到 flag

  • GET 的数据跟在 URL 后面（?what=flag），你改地址栏就行。
  • POST 的数据放在 HTTP 请求体（body）里，浏览器地址栏没有地方让你写，所以必须用"能构造请求"的手段：控制台 fetch、curl，或者 Burp 抓包改包。

可复用的思路（下次遇到同类题）

  1. 先搞清楚后端要的参数名和值（从题目代码/提示里找，这题是 what=flag）。
  2. 轻量做法：F12 → Console 用 fetch 发 POST（这题用的方式，代码见上文）。
  3. 命令行做法：curl -X POST -d "what=flag" http://目标地址。
  4. 正式做法：Burp Suite 开启拦截，正常提交一次表单，把请求改掉再放行。

延伸知识

  • Content-Type 要和 body 格式对应：表单用 application/x-www-form-urlencoded（a=1&b=2），上传文件用 multipart/form-data，JSON 接口用 application/json。格式不对后端就收不到参数。
  • fetch(url, {method, headers, body}) 是最简单的发请求方式；.then(r => r.text()) 取出响应正文。

防御视角

和 GET 一样：服务端必须独立校验参数；涉及"改状态"的接口（改密码、下单）要加 CSRF Token，防止别人伪造请求。

踩坑提示

  • body 格式写错是最常见失败原因——表单格式就是 a=1&b=2，不要顺手写成 JSON。
  • 在浏览器控制台发跨域请求可能被 CORS 拦，注意看 Console 的报错信息。
