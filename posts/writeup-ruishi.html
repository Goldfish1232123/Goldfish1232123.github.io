📚 学到的新知识

这道题的考点

用 nc 与靶机建立 TCP 连接交互 + 跨平台换行符差异导致的踩坑。

原理：为什么一开始发 ls 会报 not found

  • nc（netcat）是一个能建立 TCP 连接、双向收发数据的工具，题目给的那串数字就是 IP 和端口。
  • 连上之后本来应该发 Linux 命令（ls 列出目录、cat 读文件），但靶机一直回 ls: not found。
  • 原因是换行符不一样：Windows 的行尾是 \r\n，Linux 只认 \n。你敲的回车把 \r 也发过去了，靶机把命令当成了乱码。
  • 改用 Python 的 socket 精确控制发送的字节，问题解决。

可复用的思路（下次遇到同类题）

  1. 拿到 IP 和端口 → 连接：Windows 下用 ncat IP 端口（ncat 随 nmap 一起安装）。
  2. 连上后先试探性发 ls，能列目录就 cat flag 读文件。
  3. 如果命令一直"找不到"，先怀疑换行符/编码问题，而不是"命令打错了"。
  4. 用 Python 脚本代替交互式工具：socket.connect() → send() → recv()，完全自己控制发送内容。

延伸知识

  • nc 常用参数：-l 监听、-p 指定端口、-v 显示详细过程、-C 发送 CRLF（就是解决本题那个坑的参数）。
  • Linux 基础命令：ls（列目录）、cat（读文件）、pwd（当前路径）、cd（切换目录）。
  • TCP/socket 编程是后续 PWN、流量分析的基础，早点接触有好处。

防御视角

真实服务不应该把"可执行系统命令的交互接口"暴露在公网上；如果必须有类似的运维通道，要做强认证 + 命令白名单 + 审计日志。

踩坑提示

  • 火绒会杀掉 nc.exe（这类工具常被安全软件判定为黑客工具）——需要把它加入白名单。注意：只对自己下的靶场工具做这个操作。
  • "脚本在哪运行"要分清：Python 脚本是在我自己的电脑上跑，连的是远端靶机；不是把脚本传到靶机上。
