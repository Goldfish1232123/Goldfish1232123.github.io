writeup-贝斯家族

2026-09-27 · Bugku Crypto

📌 题目信息

  • 题目名： 贝斯家族
  • 题目平台： Bugku CTF（平台题）
  • 题目类型： Crypto / 编码转换（Base 家族）
  • 题目描述： @iH<,{bdR2H;i6*Tm,Wx2izpx2!
  • 涉及工具： Python（自己实现 Base91 解码）、CyberChef

💥 解题过程

  1. 题目名"贝斯家族"就是 Base 家族的谐音，提示这是一道 Base 系列编码题。
  2. 但明显不是 Base64：这串字符里有 @ < , { ; * !，而 Base64 的字符集只有 A-Z a-z 0-9 + /。
  3. Base 家族里允许出现大量符号的，主要是 Base85（Ascii85）、Base91、Base92。因为题目叫"贝斯家族"，先把几个都试一遍。
  4. Base91 解码后直接得到 flag： 
    输入: @iH<,{bdR2H;i6*Tm,Wx2izpx2!
输出: flag{554a5058c9021c76}
  5. Base91 的解码实现（标准码表共 91 个字符，每 13 或 14 位输出若干字节）： 
    B91 = ('ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789'
       '!#$%&()*+,./:;<=>?@[]^_`{|}~"')

def b91decode(s):
    out = bytearray(); b = n = 0; v = -1
    for ch in s:
        i = B91.find(ch)
        if i < 0:
            continue
        if v < 0:
            v = i
        else:
            v += i * 91
            b |= v << n
            n += 13 if (v & 8191) > 88 else 14
            while n > 7:
                out.append(b & 255); b >>= 8; n -= 8
            v = -1
    if v + 1:
        out.append((b | v << n) & 255)
    return bytes(out)

print(b91decode("@iH<,{bdR2H;i6*Tm,Wx2izpx2!").decode())
# flag{554a5058c9021c76}

📝 收获

这道题的考点

通过字符集判断这是 Base 家族的哪一种编码。Base64/32/85/91/92 的区分点，就在"允许出现哪些字符"和"长度规律"上。

原理：Base91 为什么要用 91 个符号

  • Base64 用 6 位表示一个"字符"，所以需要 2⁶=64 个符号；Base85 用 85 个符号，每 4 字节编码成 5 个字符，比 Base64 更省空间（这也是 PDF 里用 Ascii85 的原因）。
  • Base91 用 91 个符号，每个字符能承载 log2(91)≈6.5 位信息，因此它的实现里会出现"13 位或 14 位"的分组——这正是上面代码中 13 if (v & 8191) > 88 else 14 那行的含义。
  • 因为它把 ! @ < , { ; 这些符号都纳入了字母表，所以密文里出现大量符号，和 Base64 的"干净"长相形成鲜明对比。

可复用的思路（下次遇到同类题）

  1. 先看字符集：
    • 只有 A-Za-z0-9+/、可能以 = 结尾 → Base64
    • 全大写 + 数字 2-7、以 = 补齐 → Base32
    • 出现大量 !#$%&()*+,-./:;<=>?@[]^_`{|}~ 符号 → Base85/91/92
  2. 再看长度规律：Base64 长度是 4 的倍数；Base32 是 8 的倍数；Base85/91 没有明显倍数关系。
  3. 把 Base85、Base91、Base92 依次试一遍（CyberChef 里都有现成模块），能解出可读文本的那个就是答案。

延伸知识

  • Base 家族的共同点：都是"用一组可打印字符表示二进制数据"，区别只在符号数量和分组方式。
  • 安全场景里 Base64 很常见（传输二进制、JWT 的一部分）；但它是编码不是加密，任何人拿到都能还原——Web 题里常靠这一点做"信息泄露"。

防御视角

不要把 Base64 当作"加密"用于保护敏感数据（JWT 的 payload 只是 Base64，不是密文）；真正需要保密时必须加密并做好密钥管理。

踩坑提示

  • Base91 的码表在不同的实现里可能忽略个别符号（例如末尾的双引号），如果自己写解码器解不出来，换用在线工具再验证一次。
  • 复制密文时别漏掉符号——Base 题里少一个字符就全解不出来。
