writeup-黄道十二官

2026-09-27 · CTF Bugku Crypto

📌 题目信息

  • 题目名： 黄道十二官（社区也常写作"黄道十二宫"）
  • 题目平台： Bugku CTF（平台题）
  • 题目类型： Crypto / 古典密码（置换 + 同音替换）
  • 题目附件： 黄道十二官.jpg（一张手写符号密信的图片）
  • 涉及工具： Python（做"跳马步"重排）、AZdecrypt（同音替换求解器）

💥 解题过程

  1. 打开图片：一张泛黄的纸上排满了古怪符号（几何图形、天文符号、特殊字符混在一起），一共十几行。 这种"符号网格 + 猎奇画风"的密信，一眼就能联想到美国著名的黄道十二宫杀手（Zodiac Killer）的 340 字符密信（简称 Z340）。
  2. Z340 难在两件事叠在一起：
    • 置换（Transposition）：字符顺序被打乱，原文不是按行读的；
    • 同音替换（Homophonic substitution）：同一个字母可以对应好几个符号，专门用来破坏"统计哪个符号出现最多"的频率分析。
    所以不能直接统计频率破解，必须先还原顺序，再做替换求解。
  3. 第一层：按"跳马步"重排。把密文字符按 15 列排成矩阵，然后按国际象棋里"马"的走法读取——向下走 1 行、向右走 2 列，越界就取模回绕： 
    # 135 个字符（15×9）的跳马步重排
str_data = "%%,@*>@?==%88%5,@%#@@90-7$^=*@17,(>()1@##-$40~,*6?#%#8#=75+1(*@*1%#>,0@5)%?%*^=)>=1%,+7&#8681(+8*@@(,@@@#*=#$3*#%.#%%.3,*+7.7+@===+)61"
W = 15
for start in range(W):
    c, r = start, 0
    line = ""
    for _ in range(len(str_data) // W):
        line += str_data[r * W + c]
        r += 1
        c = (c + 2) % W
    print(line)
    跑完会得到一段"重排后的密文"——这一步就是把二维的视觉矩阵摊平成一维的逻辑字符串。
  4. 第二层：用 AZdecrypt 求解同音替换。把上一步得到的密文粘进 AZdecrypt（GitHub 上开源的 Z340 求解工具）， 运行 Solver，它会用双字符组/三字符组的统计概率（bigram / trigram）去"拼图"，自动算出最像英文的那套字母映射。
  5. 把解出的明文按题目格式整理，得到 flag：flag{alphananke}，提交通过。

📝 收获

这道题的考点

古典密码里的"两层结构"：置换负责打乱顺序、替换负责隐藏字符身份。这两层叠起来，单靠肉眼看频率是解不出来的，必须借助工具 + 明确的解题顺序。

原理：为什么要先重排、再求解

  • 置换（这里用的是"跳马步"）：把字符按 15 列摆放，再用 (行+1, 列+2) 的路径读取。这样相邻的字母在密文里会被拆得很远，破坏词组之间的关联——哪怕你猜出了符号对应的字母，按顺序读出来也还是一堆乱码。
  • 同音替换：普通替换里 E 永远对应同一个符号，数一下谁的频率最高就知道是 E。同音替换让 E 随机对应 %、*、#、@ 等多个符号，把单个符号的频率"摊平"，简单的频率分析立刻失效。
  • 为什么还是要用统计求解：虽然单字符频率被摊平了，但字母组合的概率特征还在——比如英文里 TH、HE、ING 这类组合出现得特别多。AZdecrypt 的做法是把"每种映射方案能拼出多少像英文的组合"变成一个得分，然后用爬山算法不断微调映射，直到分数最高（也就是最像英文）。
  • 顺序很重要：重排没做对，替换求解器也救不了（它面对的是被彻底打乱的字符流，统计特征全丢了）。所以要先完成物理重排，再交给求解器。

可复用的思路（下次遇到同类题）

  1. 先识别：看到几何/天文符号组成的密信网格 → 优先联想 Zodiac 系列（Z408 / Z340）、跳舞小人、银河字母等。
  2. 再分层：问自己"这题有几层？"——置换层（顺序）和替换层（字符含义）要分开处理，别指望一步到位。
  3. 层内用工具：置换层写十几行脚本就行（按列数 × 步长穷举：列宽 10~20、步长 1~3，看哪组能出可读文本）；替换层交给 AZdecrypt / 在线频率分析工具。
  4. 用"是否像英文"做判据：解出来如果能拼出自然语言单词（而不是一堆随机字母），就说明顺序对了。
  5. 积累"密码工具库"：AZdecrypt（同音替换求解）、quipqiup（简单替换在线求解）、dcode.fr（各种古典密码）、CyberChef（编码转换）。

延伸知识

  • Z340 的背景：黄道十二宫杀手在 1969 年寄给报社的三段密码之一（408、340、13 字符）。Z408 一周就被一对教师夫妇手工破了；Z340 直到 2020 年 12 月才被 David Oranchak 等人用自写程序 + AZdecrypt 破译，前后隔了 51 年。
  • Z340 的破解关键正是本题用到的那套思路：先发现"按行读不对"，尝试各种周期性的置换（19 行、15 列、对角/跳马等），再上同音替换求解器。
  • 同音替换在历史上的用途：为了对抗频率分析，古人也用"一个字母对应多个符号"的办法；现代密码学用"混淆 + 扩散"达到同样目的，但靠的是数学难题而不是手工花招。
  • CTF 里这类题的标准流程可以总结成一句话：识别密码家族 → 还原顺序 → 求解替换 → 语言校验。

防御视角

从密码学角度看，这类"置换 + 替换"的古典密码没有任何现代安全性：它不依赖密钥的数学困难性，只依赖统计特征的隐藏，而统计特征在足够长的文本面前必然暴露（这正是 Z340 最终被破的原因）。因此：真实系统的机密性必须靠现代算法（AES/RSA 等）+ 正确的密钥管理；同时也要明白"看起来乱码"绝不等于"安全"——可被统计的东西，最终都会被解开。

踩坑提示

  • 别只做一层：重排后如果直接看，会发现还是一堆乱码——这不是解题失败，而是要接着做替换求解。
  • 列宽/步长要穷举：这类题的矩阵宽度和读取步长是"人为设定"的，15 列不一定通用；脚本里把列宽 10~20、步长 1~3 都试一遍更稳。
  • 越界取模别写错：行到边界回到顶行、列到边界回绕到左边（c = (c + 2) % 15），取模写错就会整段错位。
  • 不要指望手算：340 个字符的替换求解属于计算机的活儿，用 AZdecrypt 几分钟能跑完，手工做几天也做不完。
