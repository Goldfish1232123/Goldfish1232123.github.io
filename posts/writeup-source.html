source

2026-09-12 · Web Bugku CTF

📌 题目信息

  • 题目名： source

💥 解题过程

  1. F12 打开控制台，展开代码后发现 flag，尝试后发现是假的（怎么可能这么好心啊喂）。
  2. 询问 DeepSeek 后发现 source 其实有源代码的含义，或许答案就在源代码中。
  3. 询问 DeepSeek 怎么查看源代码。
  4. 下载 git 和 python。
  5. 使用 git-dumper 工具下载源码。
  6. 使用 git reflog 查看历史记录。
  7. 使用 git show 查看历史版本的内容，发现四个里面其中一版是真的 flag。

📝 收获

这道题的考点

.git 源码泄露 + 用 Git 历史记录还原被删除的提交（本题真正的难点）。

原理：为什么这样能拿到 flag

  • 网站根目录下如果暴露了 .git 文件夹，就相当于把整个代码仓库连同全部历史提交都放在了公网上。
  • 开发者以为"把 flag 从最新代码里删掉就安全了"——错。旧提交依然躺在 Git 对象库里，只要知道提交哈希就能取出来。
  • git reflog 记录的是 HEAD 指针的每一次移动（包括被 reset 掉的提交），git show <哈希> 能看到那个版本的具体改动。这题就是从历史版本里翻出了真 flag。

可复用的思路（下次遇到同类题）

  1. 先探测：访问 http://目标/.git/，看是 404 还是能列出内容（403 说明存在但被拒绝，也有价值）。
  2. 用工具把整个仓库拖下来：git-dumper http://目标/.git/ ./dump。
  3. 翻历史：git log --all 看所有提交，git reflog 看被"丢弃"的提交记录。
  4. 看旧版本内容：git show <提交哈希>，或 git show <哈希>:flag.txt 直接看某个文件。

延伸知识

  • 其他常见源码/文件泄露：.svn、.hg、.DS_Store（Mac 目录索引）、备份文件（.bak、.swp、www.zip、wwwroot.rar）。
  • 对应工具：git-dumper、dvcs-ripper、svn-extractor。
  • 为什么这个漏洞"很可怕"：它泄露的不是一个文件，而是整个开发历史——包括曾经硬编码过的密码、密钥、测试数据。

防御视角

部署时排除 .git/.svn 等版本控制目录；用 CI/CD 只发布构建产物而不是整个源码目录；在 nginx/apache 里显式拒绝访问以 . 开头的隐藏路径。

踩坑提示

  • F12 里看到的那个 flag 是假的（题目故意放的干扰项）——这条经验值得记住：前端给的东西一律先怀疑。
  • git-dumper 依赖 Python 环境；下载中断可以直接重跑，仓库是增量下载的。
