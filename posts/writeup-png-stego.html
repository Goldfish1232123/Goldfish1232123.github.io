隐写

2026-09-27 · Misc Bugku CTF

📌 题目信息

  • 题目名： 隐写
  • 题目平台： Bugku CTF（平台题）
  • 题目类型： MISC / 图片隐写（PNG 宽高修复 + 透明像素隐写）
  • 题目描述： BUGKU{xxxx}
  • 题目附件： 压缩包，解压后是一个 2.png
  • 涉及工具： Python + Pillow（或随波逐流 / png_dim_fix 在线工具）

💥 解题过程

  1. 解压得到 2.png，用图片查看器打开——直接报错/打不开。用 Python 的 Pillow 打开也失败：cannot identify image file。
  2. 但它文件头明明是 89 50 4E 47 0D 0A 1A 0A（标准 PNG 标识），所以问题出在内部结构。手工解析 PNG 的块（chunk）结构，逐个校验 CRC： 
    [0] IHDR len=13  CRC 错误! 存储=0xcbd6df8a 计算=0xc758d77d
[1] pHYs len=9   OK
[2] iCCP len=2637 OK
[3] cHRM len=32  OK
[4] IDAT len=14904 OK
[5] IEND len=0   OK
    第 0 个块（IHDR，保存着图片的基本信息）CRC 被改坏了——这正是很多看图软件拒绝打开的原因。
  3. 进一步看 IHDR 的内容：宽 500、高 420、位深 8、颜色类型 6（RGBA）。但把 IDAT 解压后得到 1000500 字节，按 RGBA 每行 1+500×4=2001 字节算，真实高度应该是 500，而不是 420！
  4. 修复两处：把高度改成 500，然后按 PNG 规范重算 IHDR 的 CRC： 
    raw = bytearray(open("2.png","rb").read())
raw[20:24] = struct.pack(">I", 500)          # 高度改回 500
crc = zlib.crc32(bytes(raw[12:29])) & 0xFFFFFFFF
raw[29:33] = struct.pack(">I", crc)          # 重算 IHDR CRC
open("2_fixed.png","wb").write(bytes(raw))
  5. 修复后图片能打开了（500×500），但肉眼只看到一块绿色和一个黑条，没有 flag。
  6. 关键一步：统计像素发现图片里有大量完全透明的像素（alpha=0），而它们的颜色分量并不是白色： 
    RGBA(255,255,255,0) ×221062   ← 透明白（背景）
RGBA(0,0,0,0)       ×9710     ← 透明黑！
RGBA(66,163,102,0)  ×3940     ← 透明绿！
    正常看图时透明像素会显示成背景色，颜色值被"藏"起来了。把这些透明像素当白底渲染（也就是直接忽略 alpha 通道取 RGB），隐藏内容就出现了。
  7. 渲染后图片上显示出 Bugku 的 logo 和一行大字：BUGKU{a1e5aSA}。提交通过。

📝 收获

这道题的考点

PNG 文件结构（IHDR / CRC）+ 宽高修复 + "透明像素携带数据"这种隐蔽的隐写手法。三个考点叠在一起。

原理：为什么改高度、为什么透明像素能藏数据

  • PNG 由若干"块"组成，第一个块 IHDR 里保存宽、高、位深、颜色类型，并带一个 CRC32 校验值。软件加载时会先校验 CRC，CRC 不对就直接拒绝打开。
  • 出题人把高度从 500 改成 420（并且顺手改坏了 CRC），于是：① 图片打不开；② 就算打开了，也只会显示上面 420 行，下面 80 行的内容被裁掉——修复高度就能看到被藏起来的部分。
  • RGBA 图片有 4 个通道，alpha=0 表示"完全透明"。看图软件合成时会忽略透明像素的颜色，但RGB 数值仍然原样存在文件里。所以只要绕过 alpha 直接看 RGB，就能看到"透明像素里画的字"。

可复用的思路（下次遇到同类题）

  1. 图片打不开 → 先看文件头对不对，再手工解析块结构、校验 CRC，往往能立刻发现被改的地方。
  2. 看到 PNG 就先想到"宽高修复"：在线工具 png_dim_fix、随波逐流的"图片宽高修复"都能一键搞定。
  3. 图能打开但内容奇怪 → 统计像素、看 alpha 通道：
    • 把 alpha 通道单独导出看一遍；
    • 把图片"忽略 alpha 转 RGB"再渲染一遍；
    • 对 RGB/alpha 做 LSB 提取（低位隐写）。
  4. 常见图片隐写位置总结：文件尾附加数据、EXIF 元数据、PNG 宽高、LSB、调色板（PLTE）、透明通道、IDAT 里嵌文件。

延伸知识

  • PNG 关键块：IHDR（图像信息）、PLTE（调色板）、IDAT（压缩后的像素数据）、IEND（结束）、tEXt（文本注释，常藏 flag）。
  • IDAT 里的数据是 zlib 压缩的，zlib.decompress() 就能还原出像素；每行开头还有 1 字节的"过滤器类型"。
  • CRC32 的计算范围是"块类型 + 块数据"，不包含长度字段——重算时容易算错，要特别注意。

防御视角

图片里能藏东西这件事提醒我们：文件"看起来正常"不代表内容干净。企业环境里对上传的图片做二次编码（重新渲染保存）可以顺便清掉这类隐写数据和元信息。

踩坑提示

  • 修完高度别忘了同时修 CRC，否则软件还是打不开。
  • 别看到"绿色块 + 黑条"就以为图片内容就是这样——透明像素的颜色是"隐形"的，一定要单独渲染一次。
  • flag 是大写 BUGKU{a1e5aSA}，注意大小写。
