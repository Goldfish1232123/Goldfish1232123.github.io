📌 题目信息

  • 题目名： 这是一张单纯的图片

💥 解题过程

  1. 打开题目，发现下载下来一张名为 file 的 jpg 格式图片。（他都叫 file 了，而且他说图片单纯，那他肯定不单纯）
  2. 尝试改后缀，试了几个，发现 html 格式下，这个文档没提示要修复。
  3. 改成 html 格式查看，打开之后发现许多乱码，在其中发现有一串字符疑似是之前出现的 ASCII 码。

📝 收获

这道题的考点

文件真实类型看"文件头"而不是后缀名；改后缀用浏览器打开可以看到隐藏内容。

原理：为什么改后缀能看到东西

  • 一个文件是什么类型，由它开头的几个字节（Magic Number / 文件头）决定，改扩展名不会改变它的真实内容。
  • 把文件改成 .html 用浏览器打开，浏览器会按 HTML 去解析它——原本是"数据"的内容里，可读的部分就暴露出来了。
  • 这题打开后是一堆乱码，但乱码里藏着一串 ASCII 码，解码就得到 flag。

可复用的思路（下次遇到同类题）

  1. 拿到不明文件，先用 file 文件名 看系统判断的真实类型（Windows 可用 certutil 或 010 Editor 看文件头）。
  2. 用十六进制工具看开头几个字节：PNG 是 89 50 4E 47，JPG 是 FF D8 FF，ZIP 是 50 4B 03 04，PDF 是 %PDF。
  3. 尝试改后缀用浏览器/文本编辑器打开，找"看起来像编码"的字符串（ASCII 数字串、Base64、Hex、flag{）。
  4. 用 strings 文件名 直接提取所有可读文本，往往比肉眼看乱码快。

延伸知识

  • 图片隐写的常见藏法：① 文件尾部附加数据（binwalk/foremost 可分离）② EXIF 元数据（exiftool 查看）③ 像素最低位 LSB ④ PNG 宽高被改（用脚本修复）。
  • 乱码通常只是编码不对（UTF-8 用 GBK 打开就会花），换个编码再读可能就正常了。

防御视角

对外分发文件时剥离元数据；服务端做文件类型校验要用"内容检测"（读文件头）而不是只看扩展名——这也是文件上传漏洞的成因之一。

踩坑提示

  • 不是所有乱码都有价值，要学会挑出"像编码的部分"（这题就是 ASCII 数字序列）。
  • 改后缀只是手段，关键是理解"文件头决定类型"。
