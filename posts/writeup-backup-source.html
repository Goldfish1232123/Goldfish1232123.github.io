writeup-备份是个好习惯

2026-09-27 · CTF Bugku Web

📌 题目信息

  • 题目名： 备份是个好习惯
  • 题目平台： Bugku CTF（平台题，需启动场景）
  • 题目类型： WEB / 备份文件泄露 + MD5 弱比较 + 过滤器绕过
  • 题目描述： 备份是个好习惯
  • 靶机地址： 启动场景后形如 http://160.202.254.160:16492/（每人不同，会过期）
  • 涉及工具： 浏览器 / curl

💥 解题过程

  1. 打开首页，只看到一串十六进制： 
    d41d8cd98f00b204e9800998ecf8427ed41d8cd98f00b204e9800998ecf8427e
    这其实是 两个 md5("") 拼在一起（d41d8cd98f00b204e9800998ecf8427e 就是空字符串的 MD5）。说明后端在读两个变量并输出它们的 MD5，只是我们没传参。
  2. 题目名"备份是个好习惯"就是提示：去找网站留下的备份文件。试常见后缀，/index.php.bak 返回 200： 
    curl http://目标地址/index.php.bak
  3. 拿到源码（这题的全部难点都在这里）： 
    <?php
include_once "flag.php";
ini_set("display_errors", 0);
$str = strstr($_SERVER['REQUEST_URI'], '?');   // 取问号后面的部分
$str = substr($str, 1);
$str = str_replace('key', '', $str);           // 把 "key" 删掉（过滤）
parse_str($str);                               // 解析成变量
echo md5($key1);
echo md5($key2);
if (md5($key1) == md5($key2) && $key1 !== $key2) {
    echo $flag . "取得flag";
}
?>
  4. 读逻辑，目标是三件事同时成立：md5($key1) == md5($key2)、$key1 !== $key2、并且参数名要能躲过 str_replace('key','')。这正好是两类经典姿势：
    • 0e 魔术哈希：QNKCDZO 与 240610708 的 MD5 分别是 0e830400451993494058024219903391 和 0e462097431906509019562988736854，两个都是 0e 开头，弱比较时被当成数字 0 → 相等 ✓
    • 数组绕过：md5(数组) 在 PHP 5 里会报 warning 并返回 NULL，两个 NULL 相比成立；而两个不同的数组 !== 也成立 ✓
  5. 还差过滤绕过：参数名里不能出现 "key"。这里利用 str_replace() 的单次扫描特性（它不会递归检查替换后的结果）——把参数名写成 kkeyey1： 
    kkeyey1  --删掉中间的"key"-->  k + ey1 = key1   ✓
    同理 kkeyey2 → key2。
  6. 最终 payload（数组绕过）： 
    http://目标地址/?kkeyey1%5B%5D=a&kkeyey2%5B%5D=b
    返回： 
    flag{6854e8d776828b0502fefbd2ec2d65f1}取得flag
  7. 提交 flag，通过。

📝 收获

这道题的考点

三个点叠在一起：备份文件泄露（拿到源码）、MD5 弱比较绕过（0e 或数组）、过滤器的单次扫描特性（str_replace 绕过）。

原理：为什么这些"魔术"能成立

  • 为什么 0e 哈希相等：PHP 的 == 在比较两个"数字字符串"时会先转成数字。"0e123..." 和 "0e456..." 都被转成 0 → 相等。但注意：它们作为字符串并不相同，所以 !== 成立。
  • 为什么数组能绕过：md5() 期望字符串参数，传入数组时返回 NULL（PHP 5 是 warning，PHP 8 直接抛 TypeError）。NULL == NULL 为真，而两个不同数组严格比较当然不等 —— 两个条件同时满足。
  • 为什么 kkeyey1 能变回 key1：str_replace() 从头到尾扫一遍原字符串、删掉匹配的部分，不会回头再检查新拼出来的内容。所以 "kkeyey1" 里的 "key"（第 2~4 个字符）被删掉后，剩下的 "k" + "ey1" 恰好拼成 "key1"。
  • parse_str() 会把 key1[]=a 解析成数组 $key1 = ['a']，这也是数组绕过的入口。

可复用的思路（下次遇到同类题）

  1. 第一步永远是找备份/泄露文件，常用字典： index.php.bak、index.php~、index.php.swp、.index.php.swp、index.php.old、www.zip、wwwroot.zip、web.zip、backup.zip、.git/config、robots.txt……（用 Burp 的 Intruder 或 dirsearch 批量跑更快）
  2. 拿到源码后，重点找三类逻辑：比较（==）、过滤（str_replace/preg_replace）、变量注入（parse_str、$$var、extract）。
  3. 看到 md5($a) == md5($b) 就想两招：0e 魔术哈希（QNKCDZO、240610708、aabg7XSs…）或数组。
  4. 看到 str_replace('x','',...) 这种黑名单，先用嵌套思路绕：如过滤 key 就用 kkeyey；过滤 select 就用 selselectect。
  5. 发包建议用 Burp 或 curl，参数里的特殊字符（[]、%00）要正确编码。

延伸知识

  • $_SERVER['REQUEST_URI'] 是原始请求行里的路径+查询串，和 $_GET 不一样——正因为这里处理的是"原始字符串"，才让 str_replace 这种过滤有了被绕过的空间。
  • 同类 md5 考点还有：md5($a, true) 的 raw 输出比较、真正的 MD5 碰撞（两个不同文件同哈希）、SQL 注入里的 md5 弱比较登录绕过。
  • PHP 版本差异要留意：PHP 8 中 md5(数组) 会抛 TypeError（致命错误，页面直接 500），字符串与数字的比较规则也更严格，老 payload 未必通用。

防御视角

  • 不要把源码、备份、编辑器临时文件放在网站目录里（.bak/.swp/~/.git 一律要排除），Web 服务器还应拒绝访问这些后缀。
  • 比较用 ===（例如 hash_equals() 比较哈希），避免弱类型比较被利用。
  • 过滤用户输入要用白名单而不是黑名单；黑名单永远会被"嵌套写法/编码/大小写"绕过。
  • 不要用 parse_str() 把用户可控字符串直接解析进当前作用域（等于把变量覆盖权交给攻击者）。

踩坑提示

  • 方括号要 URL 编码：我第一次直接用 ?kkeyey1[]=a&kkeyey2[]=b，结果页面一片空白（参数没被正确解析）；改成 %5B%5D 才成功。这类特殊字符建议交给 Burp 或正确编码后再发。
  • 页面空白 ≠ payload 错了：PHP 遇到 md5(数组) 这类 warning 时（display_errors=0）不打印内容，要结合逻辑判断。
  • 备份文件名的后缀要"多试几个"（.bak/.swp/~/.zip），这题正是靠 index.php.bak 拿到源码的。
